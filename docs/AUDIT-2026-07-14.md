# burncpu — security and production audit (2026-07-14)

> This is the English public summary of the dated audit. The detailed Turkish
> evidence log is [AUDIT-2026-07-14.tr.md](AUDIT-2026-07-14.tr.md). A status
> refresh was recorded on 2026-07-20.

## Executive result

The audit found no open release blocker after the remediation pass. The live
stack is a single Rust/Axum container behind Cloudflare and nginx, with Postgres,
Redis and Meilisearch on a private Docker network. The app listens on container
port `3050`; only host loopback `127.0.0.1:3060` is published.

## Verified controls

- `/healthz`, `security.txt`, TLS/security headers and the public API contract
  are health-gated after deployment.
- Rust format/test/clippy, RustSec/license/source checks, gitleaks, web/mobile
  audit-build-lint, browser E2E and the isolated high-concurrency load gate are
  CI release checks.
- Session, magic-link, WebAuthn, OAuth/PKCE, TOTP, CSRF, SSRF, upload limits,
  Markdown sanitisation, audit trails and moderation escalation are covered by
  tests and the threat model.
- Production web assets use same-origin self-hosted WOFF2 fonts; the nginx CSP
  allows local styles/fonts and contains no Google Fonts dependency.

## Remaining limits

This project intentionally does not promise a media CDN, learned AI/ML
classification, multi-admin RBAC or production load generation. The one-VPS
model keeps the core legible but makes host backups, patching and capacity
planning operational responsibilities.
